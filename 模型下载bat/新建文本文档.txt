目前本人已申请workshop：
本项目计划使用进迭时空 K3 开发板、摄像头和桌面机械臂，制作一台能够理解人的话、看懂桌面物品、完成抓取和摆放，并且在抓取失败后重新观察和尝试的桌面机器人。

用户只需要说：“把红色方块放到左边。”机器人就会通过摄像头寻找红色方块，规划抓取顺序，控制机械臂完成抓取和放置，再次查看桌面，确认任务是否完成。

演示过程中，用户可以故意把物品移动位置、挡住摄像头，或者让机械臂第一次抓空。机器人需要发现原来的计划已经不适用，重新观察现场，调整动作后继续完成任务。如果连续失败，机器人会安全停止并向人请求帮助。

项目的重点不是让机械臂重复一段提前写好的动作，而是让它形成一个简单、直观的闭环：

> **听懂任务 → 看清物品 → 计划动作 → 控制机械臂 → 检查结果 → 失败后重新尝试。**

所有模型和程序提前部署在 K3 上。拔掉网线后，用户仍然可以提出新的抓取任务，机器人继续完成本地工作。
K3 上运行本地模型、视觉程序、任务管理程序和机械臂控制程序。系统默认不依赖外部搜索或云端接口，演示时通过关闭网络验证本地自治能力。
项目同时保留一个可独立使用的本地 Agent 工作台。用户可以像使用类 Codex 工作台一样，在网页中查看对话、任务步骤、工具调用、模型状态和记忆内容；也可以自由选择不同大小的本地模型和调用强度。这样，项目既是一台能动手的机器人，也是一套可以观察和控制机器人的本地 Agent 软件。

解决什么问题：
1. 目前很多机器人只能执行固定动作
传统桌面机械臂通常需要提前写好坐标和动作。一旦物品位置变了，或者用户临时改变要求，机器人就可能抓错、抓空，或者停在原地。
本项目希望让机器人能够先观察现场，再决定动作，而不是只执行一套固定脚本。
2. 机器人通常不会检查自己是否成功
很多演示只展示“机械臂动了”，却没有回答“物品有没有真的被抓起来”和“物品有没有放到正确位置”。
本项目要求每次动作后重新查看现场，确认物品位置是否符合预期。只有确认成功，任务才算完成。
3. 机器人遇到变化后不会自己调整
人在机器人准备抓取时移动物品，或者故意遮挡目标，机器人需要重新获取画面、更新目标位置并重新规划，而不是继续使用旧坐标。
 4. 云端服务不适合现场互动
如果每次识别和决策都需要联网，现场网络不稳定时机器人就无法工作，也无法证明任务确实是在 K3 本地完成的。
本项目将模型和核心程序放在 K3 上，专门设计断网演示，验证机器人在没有外网的情况下仍能完成任务。

用户如何使用：
用户可以输入或说出
- “把红色方块放到左边。”
- “把桌面上的蓝色物品整理到盒子里。”
- “红色的放左边，黄色的放右边，蓝色的不要动。”
- “等等，黄色的也不要动了。”
机器人会把人的要求转换成几个简单动作，例如：寻找物品、移动到物品上方、抓取、移动到目标区域、放下、再次检查。用户可以在执行过程中看到当前使用的模型、已经调用的工具和任务进度。

配套的本地 Agent 工作台：
现有项目已经有一个中文本地 Agent 工作台，作为机器人的“大脑和控制台”。它包括：
- 用户可以自由选择 Qwen3 4B、8B、14B 等本地模型；
- 可以选择快速、平衡、深度等不同调用强度；
- Agent 能够调用工作区、计算、时间、摄像头和机械臂等工具；
- 可以查看模型回复、工具调用结果和任务执行过程；
- 可以保存对话和任务记忆，方便继续之前的工作；
- 提供类似 Codex 的多栏工作界面，集中显示对话、工作区和运行状态；
- 默认关闭外网，支持在本地和断网环境中运行。
机械臂只是这个 Agent 新增的一组可执行工具。今后也可以在同一个工作台中接入其他摄像头、传感器或机器人。

Agent 工作台和工具调用：
本项目已有的 Agent 不是一个只能返回文字的聊天窗口，而是可以按照任务需要调用工具。它会先理解用户要求，再选择合适的工具，例如读取摄像头、定位物品、控制机械臂、检查抓取结果或读取任务记录。
当前本地模型调用和工具处理已经能够控制在 10 秒以内，申请书将“普通任务首次响应小于 10 秒”作为软件体验目标。用户可以根据任务需要选择 4B、8B 或 14B 模型：4B 适合快速响应，8B 适合日常任务，14B 适合更复杂的规划。模型切换不改变机械臂工具和安全规则。
工作台还会展示当前模型、调用强度、工具步骤、响应时间和任务状态，让观众能看见机器人不是提前播放脚本，而是在现场由 Agent 组织动作。
